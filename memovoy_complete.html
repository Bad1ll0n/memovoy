Sistema de Denúncia de Posts

Moderação humana em segunda linha — complementa a moderação automática por visão computacional já existente

Fluxo de denúncia — perspetiva do utilizador
Passo 1
Utilizador clica "..." no post → "Denunciar"
Botão presente em todos os posts, comentários e perfis. Nunca na rota principal — está no menu de opções secundário.
Passo 2
Seleciona categoria
Conteúdo inapropriado · Spam ou publicidade · Informação falsa · Violação de privacidade · Incitação ao ódio · Outro
Passo 3
Confirmação instantânea
"Obrigado — a tua denúncia foi registada. Analisamos normalmente em menos de 24h."
Auto
Limiar automático de ocultação
Se o mesmo post recebe 5+ denúncias independentes em menos de 1h, fica automaticamente oculto até revisão humana — sem remover permanentemente.
Revisão
Moderador humano decide em <24h
Remover permanentemente · Restaurar e ignorar denúncia · Avisar o autor · Suspender conta. Denunciante recebe notificação do resultado.

Schema da tabela no PostgreSQL
-- Tabela de denúncias
CREATE TABLE reports (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  reporter_id UUID NOT NULL REFERENCES users(id),
  target_type VARCHAR(20) NOT NULL,  -- 'post' | 'comment' | 'profile'
  target_id   UUID NOT NULL,
  category    VARCHAR(40) NOT NULL,  -- 'inappropriate' | 'spam' | 'misinformation' | ...
  note        TEXT,
  status      VARCHAR(20) DEFAULT 'pending',  -- 'pending' | 'resolved' | 'dismissed'
  moderator_id UUID REFERENCES admins(id),
  resolution  VARCHAR(20),           -- 'removed' | 'restored' | 'warned' | 'banned'
  created_at  TIMESTAMPTZ DEFAULT NOW(),
  resolved_at TIMESTAMPTZ,
  UNIQUE(reporter_id, target_id)     -- um user só pode denunciar o mesmo conteúdo uma vez
);

-- Index para fila de moderação ordenada por urgência
CREATE INDEX idx_reports_pending ON reports(status, created_at)
  WHERE status = 'pending';

-- View para contar denúncias por conteúdo (trigger de ocultação automática)
CREATE VIEW report_counts AS
  SELECT target_id, target_type, COUNT(*) as total
  FROM reports WHERE status = 'pending'
  AND created_at > NOW() - INTERVAL '1 hour'
  GROUP BY target_id, target_type
  HAVING COUNT(*) >= 5;
Regras anti-abuso do sistema de denúncias
Rate limiting por utilizador
Máx. 10 denúncias por hora por utilizador. Contas novas (<7 dias) limitadas a 3/hora.
Deteção de denúncias coordenadas
Se 5+ denúncias vierem de contas criadas no mesmo dia, são sinalizadas como suspeitas e não acionam ocultação automática.
Proteção contra denúncias falsas
Utilizadores que denunciam repetidamente conteúdo que é depois restaurado recebem redução do peso das suas denúncias futuras.
Recurso pelo autor
Autor cujo conteúdo foi removido pode submeter recurso uma única vez, com nota explicativa. Revisão por moderador diferente.

Princípios dos empty states do MemoVoy
Nunca um ecrã em branco.

Cada estado vazio tem ícone, título, descrição curta e pelo menos uma ação.

A ação principal é sempre construtiva.

Em vez de "sem resultados", oferece "cria o primeiro". Transforma frustração em engagement.

Tom consistente com a marca.

Viagem, descoberta, aventura — mesmo nos erros. Nunca mensagens técnicas expostas ao utilizador.

Erros técnicos sempre com código.

O código de erro (NET_001, AI_002) é invisível para utilizadores normais mas ajuda no suporte técnico.

AI Fallback Graceful

Quando a Anthropic API falha, o MemoVoy nunca mostra um ecrã de erro — serve sempre um roteiro de qualidade

Arquitetura do sistema de fallback
Nível 1 — Geração em tempo real (caminho normal)
API disponível

Wizard completo → Prompt compiler → Anthropic API → Validação → Roteiro personalizado.

Tempo médio: 8–15 segundos. Qualidade: máxima (totalmente personalizado).

Nível 2 — Fallback por destino (API em baixo)
API indisponível

Serve roteiro pré-gerado de alta qualidade para o destino solicitado, adaptado ao grupo e duração. Armazenado no Redis com TTL de 30 dias e regenerado semanalmente.

Tempo de resposta: <1 segundo. Qualidade: alta (não personalizado por preferências específicas).

⚠️ Mensagem ao utilizador: "Gerámos um roteiro base para Tóquio — quando os nossos servidores estiverem mais tranquilos, personalizamos automaticamente para ti."
Nível 3 — Fallback manual (destino sem cache)
API + cache indisponíveis

Para destinos fora do top 50, serve o modo de criação manual com sugestões de POIs (base de dados própria, sem IA). O utilizador constrói o roteiro com assistência estática.

Tempo de resposta: imediato. Qualidade: média (requer esforço do utilizador).

ℹ️ Mensagem: "A geração automática está temporariamente indisponível. Aqui está o modo manual com sugestões para o teu destino."

Pipeline de regeneração automática semanal
# cron job — todos os domingos às 3h UTC
# regenerate_fallback_itineraries.py

async def regenerate_fallbacks():
    destinations = await get_top_destinations(limit=50)

    for dest in destinations:
        for group_type in ['solo', 'couple', 'friends', 'family']:
            for duration in [3, 5, 7]:
                itinerary = await generate_with_ai(
                    destination=dest,
                    group=group_type,
                    days=duration,
                    transport='public',   # default para fallback
                    budget='medium'
                )
                await redis.setex(
                    key=f"fallback:{dest}:{group_type}:{duration}d",
                    value=itinerary,
                    ttl=30 * 24 * 3600  # 30 dias
                )
