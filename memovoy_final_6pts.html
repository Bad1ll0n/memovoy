1. Calculador de Pegada de Carbono

Primeiro diferenciador ambiental numa rede social de viagens. Calcula automaticamente com base no roteiro.

ℹ
A pegada de carbono é calculada automaticamente a partir dos dados já existentes no roteiro: transportes entre atividades, distâncias geo calculadas pelo PostGIS, duração e tipo de alojamento. Não requer input manual do utilizador.

Como funciona o cálculo

✈ Voo
Base: 255g CO₂/km por passageiro em classe económica. Short-haul (<1500km): ×1.2. Long-haul: ×1.0. Fonte: ICAO Carbon Emissions Calculator.
🚗 Carro
120g CO₂/km (gasolina média). Elétrico: 20g/km. Partilhado: divide por número de pessoas.
🚆 Comboio
14g CO₂/km (média europeia). Eurostar: 6g/km. Varia por país e rede elétrica.
🏨 Alojamento
Hotel: 23kg CO₂/noite. Airbnb/apartamento: 11kg/noite. Hostel: 7kg/noite. Boutique: 18kg/noite.
🚶 A pé / Bicicleta
0g CO₂. A IA usa isto para destacar roteiros de baixo impacto e sugerir dias a pé.
⚡ Compensação
Link para parceiros de offsetting certificados (Gold Standard). Opcional — nunca obrigatório.

-- Função PostgreSQL para calcular CO₂ de um roteiro
CREATE OR REPLACE FUNCTION calculate_itinerary_carbon(p_itinerary_id UUID)
RETURNS JSONB AS $$
DECLARE
  result JSONB;
BEGIN
  WITH transport_emissions AS (
    SELECT
      transport_mode,
      -- distância calculada via PostGIS já existente
      ST_Distance(from_geo, to_geo) / 1000.0 AS distance_km,
      CASE transport_mode
        WHEN 'flight'   THEN 255   -- g CO₂/km
        WHEN 'car'     THEN 120
        WHEN 'train'   THEN 14
        WHEN 'bus'     THEN 68
        WHEN 'taxi'    THEN 150
        WHEN 'walking' THEN 0
        WHEN 'bicycle' THEN 0
        ELSE 100
      END AS emission_factor
    FROM itinerary_transports
    WHERE itinerary_id = p_itinerary_id
  ),
  accom_emissions AS (
    SELECT
      duration_nights * CASE accommodation_type
        WHEN 'hotel'   THEN 23000  -- g CO₂/noite
        WHEN 'airbnb'  THEN 11000
        WHEN 'hostel'  THEN 7000
        ELSE 15000
      END AS grams
    FROM itineraries WHERE id = p_itinerary_id
  )
  SELECT jsonb_build_object(
    'total_kg',    ROUND((SUM(te.distance_km * te.emission_factor) + ae.grams) / 1000),
    'transport_kg', ROUND(SUM(te.distance_km * te.emission_factor) / 1000),
    'accom_kg',    ROUND(ae.grams / 1000),
    'breakdown',   jsonb_agg(jsonb_build_object(
      'mode', te.transport_mode,
      'kg',   ROUND(te.distance_km * te.emission_factor / 1000)
    ))
  ) INTO result
  FROM transport_emissions te, accom_emissions ae
  GROUP BY ae.grams;

  RETURN result;
END;
$$ LANGUAGE plpgsql;

5. Certificate Pinning

Protege as apps iOS e Android contra ataques man-in-the-middle em redes comprometidas (Wi-Fi de hotel, aeroporto).

⚠
Atenção operacional: certificate pinning requer um processo de atualização de certificado antes da expiração — se o pin expirar sem update da app, todas as apps antigas ficam offline. Implementar sempre com pelo menos 2 pins (atual + backup) e alertas antecipados de 90 dias.

Como funciona

Normal
App → servidor: apresenta certificado SSL
O sistema operativo valida a cadeia de certificados (CA chain) — comportamento padrão.
Com pinning
App verifica também o hash do certificado
Compara o certificado apresentado com o hash hard-coded na app. Se não bater certo, a ligação é recusada — mesmo que o CA seja válido.
Ataque
Certificado falso é recusado
Proxy de intercepção (Burp Suite, Charles Proxy) tem um certificado diferente — o pin não bate certo e a ligação falha com erro claro.

Implementação

// iOS — Swift com URLSession
class PinnedSessionDelegate: NSObject, URLSessionDelegate {
  // SHA-256 hash do certificado público (não a chave privada)
  let pinnedHashes: Set<String> = [
    "sha256/xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx=",  // certificado atual
    "sha256/yyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyy="   // backup (próximo)
  ]

  func urlSession(_ session: URLSession,
    didReceive challenge: URLAuthenticationChallenge,
    completionHandler: @escaping (URLSession.AuthChallengeDisposition, URLCredential?) -> Void)
  {
    guard
      challenge.protectionSpace.authenticationMethod == NSURLAuthenticationMethodServerTrust,
      let serverTrust = challenge.protectionSpace.serverTrust,
      let certificate = SecTrustGetCertificateAtIndex(serverTrust, 0)
    else {
      completionHandler(.cancelAuthenticationChallenge, nil)
      return
    }

    let certData = SecCertificateCopyData(certificate) as Data
    let hash = "sha256/" + certData.sha256Base64()

    if pinnedHashes.contains(hash) {
      completionHandler(.useCredential, URLCredential(trust: serverTrust))
    } else {
      // Log para Datadog — possível ataque ou certificado expirado
      Logger.security.error("Certificate pin mismatch: \(hash)")
      completionHandler(.cancelAuthenticationChallenge, nil)
    }
  }
}

// Android — OkHttp CertificatePinner
val certificatePinner = CertificatePinner.Builder()
  .add("api.memovoy.com", "sha256/xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx=")
  .add("api.memovoy.com", "sha256/yyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyy=")
  .build()

val client = OkHttpClient.Builder()
  .certificatePinner(certificatePinner)
  .build()

Processo de rotação de certificado

✓
90 dias antes da expiração: alerta automático no Datadog. Preparar novo certificado e calcular o seu hash.
✓
60 dias antes: lançar versão da app com os 2 pins (atual + novo). Ambos são aceites.
✓
No momento da rotação: trocar certificado no servidor. Apps antigas continuam a funcionar com o pin do novo certificado.
✓
30 dias depois: lançar versão que remove o pin antigo. Apps muito antigas que não atualizaram ficam offline — forçar update.
ℹ
O pinning aplica-se apenas às apps nativas iOS e Android. Na Web, o browser gere a validação de certificados — certificate pinning web (HPKP) foi depreciado em 2018 por causar mais problemas do que resolvia.

Implementação técnica

-- Query: sessões ativas do utilizador para o ecrã de gestão
SELECT
  s.id,
  s.created_at,
  s.expires_at,
  s.is_suspicious,
  d.device_name,
  d.platform,
  d.last_seen_at,
  d.last_ip_country,
  (d.id = current_device_id) AS is_current
FROM user_sessions s
LEFT JOIN user_devices d ON d.device_id = s.device_fingerprint
WHERE
  s.user_id = $1
  AND s.revoked_at IS NULL
  AND s.expires_at > NOW()
ORDER BY
  is_current DESC,   -- este dispositivo sempre primeiro
  d.last_seen_at DESC;

-- Revogar sessão específica
UPDATE user_sessions
SET revoked_at = NOW()
WHERE
  id = $1
  AND user_id = $2  -- garantir que o user só revoga as suas próprias sessões
  AND revoked_at IS NULL;

-- O token JWT correspondente fica inválido na próxima verificação
-- (a tabela user_sessions é a source of truth para validade)

7. Previsão de Affluência

IA usa dados reais da comunidade MemoVoy para prever quando cada local está mais lotado — cresce com a plataforma.

✓
Diferenciador único: ao contrário do Google Maps (dados de localização anónimos genéricos), o MemoVoy usa dados de utilizadores reais com roteiros — sabe não apenas que alguém passou por um local, mas quando, por quanto tempo e no contexto de que tipo de viagem.

Fontes de dados (por fase)

MVP — dados externos
Google Places "popular times" via API. Datasets públicos de turismo (Eurostat, OMT). Serve como base antes de ter dados próprios.
v1.1 — dados MemoVoy
Atividades dos roteiros com horários + posts geo-tagged com timestamp. Agrupados por local, hora e dia da semana. Começa a ser relevante a partir de ~50k roteiros.
v2.0 — modelo próprio
Modelo de ML treinado em dados MemoVoy + sazonalidade + eventos locais (feriados, festivais). Previsões por hora com intervalo de confiança.

Pipeline de dados para o modelo

-- Agregação de affluência por local e hora (job diário)
-- Fonte: itinerary_activities (localizações + horários reais)

INSERT INTO location_crowding_stats (
  location_geo_hash,
  location_name,
  day_of_week,
  hour_of_day,
  avg_visit_count,
  sample_size,
  last_updated
)
SELECT
  ST_GeoHash(location, 7) AS geo_hash,  -- agrupa locais próximos
  MODE() WITHIN GROUP (ORDER BY name) AS location_name,
  EXTRACT(DOW FROM i.start_date + a.start_time) AS day_of_week,
  EXTRACT(HOUR FROM a.start_time) AS hour_of_day,
  COUNT(*) AS avg_visit_count,
  COUNT(*) AS sample_size,
  NOW() AS last_updated
FROM itinerary_activities a
JOIN itinerary_days d ON a.day_id = d.id
JOIN itineraries i ON d.itinerary_id = i.id
WHERE
  a.location IS NOT NULL
  AND a.start_time IS NOT NULL
  AND i.status = 'published'
  AND a.deleted_at IS NULL
GROUP BY geo_hash, day_of_week, hour_of_day
ON CONFLICT (location_geo_hash, day_of_week, hour_of_day)
DO UPDATE SET
  avg_visit_count = EXCLUDED.avg_visit_count,
  sample_size = EXCLUDED.sample_size,
  last_updated = NOW();
