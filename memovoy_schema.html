Decisões de design críticas

🔑 Primary keys: UUID v7 em todas as tabelas
Auto-increment integers expõem o volume de dados (um utilizador vê que é o user #1247 e sabe quantos utilizadores existem). UUIDs v4 puros degradam índices B-tree porque são aleatórios. UUID v7 resolve ambos: time-ordered para performance, opacos para segurança.
✓ UUID v7 via pg_idkit extension
🌍 Data residency: coluna db_region em users
Cada utilizador tem um campo db_region ('eu-central-1' ou 'sa-east-1'). O API layer lê este campo no login e roteia todos os pedidos subsequentes para a base de dados correta. Dados EU ficam em Frankfurt, dados BR ficam em São Paulo — obrigatório por RGPD e LGPD.
✓ Routing por db_region no connection layer
🗑 Soft deletes em todas as tabelas de conteúdo
Posts, roteiros, comentários e contas nunca são apagados fisicamente — têm um campo deleted_at TIMESTAMPTZ. Isto permite: recuperar conteúdo apagado por engano, cumprir RGPD com anonimização em vez de DELETE, e manter integridade referencial sem cascades problemáticas.
✓ deleted_at nullable + índices parciais excluem soft-deleted rows
⏱ Timestamps: sempre TIMESTAMPTZ, nunca TIMESTAMP
TIMESTAMP sem timezone armazena a hora local do servidor. Quando o servidor muda de timezone ou migra para outra região, os dados ficam inconsistentes. TIMESTAMPTZ armazena sempre em UTC e converte para o timezone do utilizador na aplicação.
✓ TIMESTAMPTZ everywhere · conversão no frontend
📍 Geometria: PostGIS GEOGRAPHY, não GEOMETRY
GEOMETRY faz cálculos em plano cartesiano — funciona para áreas pequenas mas distorce a distâncias maiores (a Terra é redonda). GEOGRAPHY faz cálculos na esfera — distâncias em metros corretas em qualquer parte do mundo. Essencial para "atividades a menos de 500m" e desafios geo.
✓ GEOGRAPHY(POINT, 4326) para todas as localizações

CREATE EXTENSION IF NOT EXISTS "postgis";          -- geo queries
CREATE EXTENSION IF NOT EXISTS "pg_idkit";         -- UUID v7
CREATE EXTENSION IF NOT EXISTS "pg_trgm";          -- full-text search
CREATE EXTENSION IF NOT EXISTS "btree_gin";        -- GIN indexes em arrays
CREATE EXTENSION IF NOT EXISTS "pgcrypto";         -- encriptação PII
CREATE EXTENSION IF NOT EXISTS "timescaledb";      -- time-series para analytics

-- Helper function: UUID v7 como default
CREATE OR REPLACE FUNCTION generate_ulid()
RETURNS UUID AS $$ SELECT idkit_uuidv7() $$ LANGUAGE SQL;

Índices críticos & Infra

Os índices que fazem a diferença entre uma query de 2ms e uma de 8 segundos

ℹ
Índices têm custo: aceleram leituras mas abrandam escritas e ocupam espaço. Cada índice abaixo tem uma justificação — não indexar tudo por defeito.
-- ============================================
-- UTILIZADORES
-- ============================================

-- Login por email: O caminho mais crítico de toda a app
CREATE UNIQUE INDEX idx_users_email_hash
  ON users(email_hash)
  WHERE deleted_at IS NULL;

-- Username lookup para perfis públicos
CREATE UNIQUE INDEX idx_users_username
  ON users(username)
  WHERE deleted_at IS NULL;

-- Social graph: quem segue quem
CREATE INDEX idx_follows_following
  ON follows(following_id, follower_id)
  WHERE status = 'active';

-- Sessões por utilizador: revogar todas de um user
CREATE INDEX idx_sessions_user
  ON user_sessions(user_id)
  WHERE revoked_at IS NULL;

-- ============================================
-- ROTEIROS
-- ============================================

-- Feed de roteiros de um utilizador
CREATE INDEX idx_itineraries_user_published
  ON itineraries(user_id, published_at DESC)
  WHERE status = 'published' AND deleted_at IS NULL;

-- Pesquisa por país (top países do mês)
CREATE INDEX idx_itineraries_country_month
  ON itineraries(country_code, date_trunc('month', published_at))
  WHERE status = 'published' AND deleted_at IS NULL;

-- Geo search: roteiros perto de uma localização
CREATE INDEX idx_itineraries_geo
  ON itineraries USING GIST(destination_geo)
  WHERE status = 'published';

-- Atividades por localização (geo challenges)
CREATE INDEX idx_activities_location
  ON itinerary_activities USING GIST(location)
  WHERE deleted_at IS NULL;

-- ============================================
-- SOCIAL
-- ============================================

-- Feed por data de publicação
CREATE INDEX idx_posts_user_created
  ON posts(user_id, created_at DESC)
  WHERE deleted_at IS NULL AND is_hidden = false;

-- Moderação: posts com mais denúncias primeiro
CREATE INDEX idx_reports_pending
  ON reports(status, created_at)
  WHERE status = 'pending';

-- ============================================
-- IA & ML
-- ============================================

-- Feedback loop: edições de roteiros IA por destino
CREATE INDEX idx_edits_generation
  ON itinerary_edits(generation_id, edit_type, created_at);

-- Feed interactions para treino ML (últimos 90 dias)
CREATE INDEX idx_feed_interactions_user_recent
  ON feed_interactions(user_id, created_at DESC)
  WHERE created_at > NOW() - INTERVAL '90 days';

-- ============================================
-- PESQUISA FULL-TEXT (pg_trgm)
-- ============================================

-- Pesquisa por nome de destino
CREATE INDEX idx_itineraries_destination_trgm
  ON itineraries USING GIN(destination_name gin_trgm_ops)
  WHERE status = 'published';

-- Pesquisa por username
CREATE INDEX idx_users_username_trgm
  ON users USING GIN(username gin_trgm_ops)
  WHERE deleted_at IS NULL;

Triggers essenciais

-- Manter contadores desnormalizados em sync
-- (mais rápido que COUNT(*) em cada query)

CREATE OR REPLACE FUNCTION update_post_likes_count()
RETURNS TRIGGER AS $$
BEGIN
  IF TG_OP = 'INSERT' THEN
    UPDATE posts SET likes_count = likes_count + 1
      WHERE id = NEW.target_id AND NEW.target_type = 'post';
  ELSIF TG_OP = 'DELETE' THEN
    UPDATE posts SET likes_count = GREATEST(likes_count - 1, 0)
      WHERE id = OLD.target_id AND OLD.target_type = 'post';
  END IF;
  RETURN NULL;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_post_likes
  AFTER INSERT OR DELETE ON reactions
  FOR EACH ROW EXECUTE FUNCTION update_post_likes_count();

-- Trigger semelhante para: follows → user.follower_count
-- saves → itinerary.saves_count
-- posts → user_profiles.total_trips

Migrations sem downtime

Como alterar o schema com 100M de registos sem parar a app

⚠
A regra de ouro: nunca fazer ALTER TABLE que bloqueie a tabela inteira. Em PostgreSQL, adicionar uma coluna NOT NULL sem DEFAULT, ou criar um índice sem CONCURRENTLY, bloqueia a tabela e derruba a app em produção.
✗ Nunca fazer isto em produção
-- Bloqueia a tabela inteira!
ALTER TABLE posts
  ADD COLUMN score INTEGER NOT NULL DEFAULT 0;

-- Bloqueia escritas durante horas!
